# 교수자용 채점 가이드 — 학생 배포 금지

## 1. 배포와 채점 원칙

학생에게는 영어로 작성된 `../student/assignment.md`, `../student/problem-definition-template.md`, `../student/problem-definition-example.md`만 배포한다. 첫 파일에 학생 공개용 상세 평가 기준이 포함되어 있다. 예시는 별도의 가상 메이커스페이스 문제를 사용하며 영화 문제의 히든 포인트를 설명하지 않는다. 이 파일과 이 폴더를 포함한 상위 폴더 전체를 학생에게 전달하지 않는다.

학생 제출물은 `problem-definition.md`, `demo.html`, `proposal.html`이다. 기본 배점은 50 / 25 / 25로 총 100점이며, 심화 가산점은 최대 10점이다. 총점 상한은 110점이다. 학생용 안내에 가산점의 존재와 일반 원칙은 공개하되 아래의 구체적인 발견 포인트는 공개하지 않는다.

이 과제는 제한된 관측으로부터 문제를 정의하고, 추가 정보와 해법·검증을 설계하여 영화사에 제안하는 종합 사고력을 평가한다. 특정 모델이나 제품의 재현을 정답으로 두지 않는다.

현재 안내는 개별 또는 팀 운영에 모두 쓸 수 있다. 마감일, 개인/팀 여부, 발표 시간과 수업 성적 반영 비율은 실제 배포 시 강의 운영 조건에 맞춰 덧붙인다. 별도 구두 방어는 현재 학생용 필수 제출 요건에 포함하지 않았다.

## 2. 공개 평가 기준과 배점

| 제출물 | 평가 항목 | 배점 |
|---|---|---:|
| 문제 정의서 | 문제 범위·사용 목적·분류 | 10 |
| 문제 정의서 | 계산 가능한 문제 정의 | 15 |
| 문제 정의서 | 데이터 해석·가정·추가 정보 | 10 |
| 문제 정의서 | 접근 선택·검증 계획 | 10 |
| 문제 정의서 | LLM 활용과 본인 검토 | 5 |
| 데모 | 핵심 흐름의 실행 | 10 |
| 데모 | 문제 정의서와의 일치 | 8 |
| 데모 | 확인 가능성·재현성 | 7 |
| 제안 발표 | 문제와 가치의 전달 | 7 |
| 제안 발표 | 제안의 논리와 근거 | 8 |
| 제안 발표 | 실행 가능한 도입 제안 | 7 |
| 제안 발표 | 발표의 명료성 | 3 |
| **합계** | | **100** |

모든 항목에 공통으로 다음 수준을 적용한다. 항목 안에서 부분 점수를 줄 수 있다.

- 충분: 구체적인 정의·근거가 있고 다른 산출물에서도 일치하며 확인할 수 있다.
- 부분 충족: 개념은 타당하나 필요한 정보, 연결 또는 확인 근거가 일부 빠져 있다.
- 피상적: 용어나 선언만 있고 그 문제에 적용한 설명이 부족하다.
- 미충족: 없거나 핵심 의미가 잘못되었으며 결과에 영향을 준다.

미확정 사항을 정확히 식별하고 확인 계획을 세운 답을, 근거 없이 값을 채운 답보다 높게 평가한다. 분류는 선택한 범위 안에서 판단한다. 일회성 편성, 반복적 재편성, 예측 분석은 같은 분류를 강요하지 않는다. 분석 모듈의 순서만으로 Hierarchical, 시계열 데이터만으로 Stateful, 반복 실행만으로 Feedback이라고 판단하면 해당 근거를 검토한다.

## 3. 히든 채점 포인트: 구매자와 실제 관객의 차이

### 숨겨 둔 조건

예매한 회원과 해당 구매의 티켓 수는 알 수 있으나, 동반 관람객이 누구인지는 알 수 없다. 학생용 자료는 거래 기록의 필드를 정확히 제시하되 이 한계를 직접 설명하지 않는다.

학생이 알아차려야 할 핵심은 다음과 같다.

- 구매자 ID와 구매 티켓 수로 실제 관람자 전원을 식별할 수는 없다.
- 구매자의 기록을 모든 티켓에 동일하게 복제하면 다른 사람의 선호를 구매자의 선호로 잘못 귀속할 수 있다.
- 한 사람의 기록도 본인의 취향 외에 동행·대리 구매 등 여러 설명과 양립할 수 있다. 어떤 설명이 실제 사실인지는 별도 확인이 필요하다.
- 티켓 수 예측과 고유 관객 수·개인 선호 추정은 서로 다른 대상이며, 관측 단위에 맞게 목표를 정해야 한다.

### 배점

공개 항목인 **데이터 해석·가정·추가 정보 10점 안에 5점**을 배정한다. 별도 감점을 추가하지 않는다.

| 관찰 수준 | 점수 |
|---|---:|
| 구매자와 전체 관람자를 구분하고, 동반자 식별 한계를 명시 | 0~2 |
| 그 한계가 분석 단위·선호 추정·고유 인원·평가 등에 주는 영향을 설명 | 0~2 |
| 범위 축소, 가정·민감도 처리, 추가 확인 등 타당한 대응을 제시 | 0~1 |

나머지 5점은 다른 데이터의 의미·품질·가정 처리와 추가 정보 요청의 구체성에 배정한다. 숨겨진 조건을 몰랐다는 이유로 공개 배점 밖에서 일괄 감점하거나 총점 상한을 두지 않는다. 다른 항목에서도 실제로 모순이나 과장된 주장이 나타나면 해당 항목의 기준으로만 판단한다.

정답 용어를 요구하지 않는다. ‘동반자’라는 말을 쓰지 않아도 거래 단위와 관람자 단위의 불일치를 정확히 설명하면 인정한다. 실제 인물의 정체를 복원하는 방법이나 직접 식별정보 수집을 요구하지 않는다. 개인 단위 모델을 포기하고 구매 건 또는 티켓 단위로 범위를 조정하는 답도 타당할 수 있다.

## 4. 심화 가산점: 최대 10점

### A. 편성에 따라 관객 선택과 실현 수요가 달라짐: 최대 6점

수요를 고정된 외생값으로 두고 편성에 배분하는 접근의 한계를 학생이 스스로 발견하는지 본다.

| 수준 | 가산점 |
|---|---:|
| 편성·시간·접근 가능성 등 공급 조건이 관객 선택과 실현 수요를 바꿀 수 있다고 설명 | 0~2 |
| 대체 영화·시간대로의 이동, 관람 포기, 용량 제한 등 선택 구조를 모델·데모 또는 명확한 계산 설계에 반영 | 0~2 |
| 편성 후보를 공통 조건에서 비교하고, 관측 상관관계와 편성 변경의 효과를 구분할 검증 계획을 제시 | 0~2 |

‘예측 후 편성’이라는 기본 접근 자체를 감점하지 않는다. ‘Feedback’이라는 분류명만으로 가점을 주지 않는다. 고정된 한 시점의 편성 후보 평가도 편성별 관객 반응을 다룰 수 있으며, 이것은 반드시 운영 중 재계획을 뜻하지 않는다.

복잡한 선택 모델의 완성보다 행동 가정, 대안 간 비교, 데이터로 검증해야 할 관계의 구분을 본다. 결과 숫자를 편성에 따라 임의 변경한 경우에는 반영으로 인정하지 않는다.

### B. 합성 소비자 또는 이에 준하는 불확실성 처리: 최대 4점

관측 기록만으로 소비자 구성이나 선호가 하나로 결정되지 않는다는 점을 이해하고, 복수의 가능한 세계를 다루는지 본다.

| 수준 | 가산점 |
|---|---:|
| 합성 소비자·집단·잠재 유형 등을 관측 사실과 구분하고 가정을 명시 | 0~1 |
| 관측 가능한 통계와 양립하는 복수 구성 또는 시나리오를 설계 | 0~1 |
| 구성·선호·행동 가정이 달라질 때 결과나 제안 결정의 민감도·견고성을 비교 | 0~1 |
| 추가 데이터로 가정을 좁히거나 대안을 검증할 방법을 제안 | 0~1 |

‘합성 소비자’라는 용어 자체는 필수가 아니다. 동등한 문제 인식을 가진 잠재변수, 확률적 시나리오, 불확실성 범위 등의 접근도 인정한다. 단순히 난수로 사람 프로필을 생성하거나 LLM에게 가상의 성격을 부여한 것만으로는 충분하지 않다. 가상 소비자를 실제 회원·실제 동반자의 복원 결과로 주장하면 그 타당성을 인정하지 않는다.

기본점에서는 문제 정의의 충실도를, 가산점에서는 심화 발견을 접근·비교·검증으로 발전시킨 정도를 본다. 같은 문장을 발견했다는 이유만으로 여러 세부 가산점을 자동 부여하지 않는다.

## 5. 추가 정보 요청의 평가 참고 — 학생에게 정답 목록으로 배포하지 않음

아래는 가능한 요청의 예시이며 필수 목록이 아니다. 학생이 선택한 범위에서 정보의 필요성, 획득 가능성, 우선순위와 미확보 시 대안을 설명하는지가 중요하다.

| 정보 후보 | 평가할 사고 |
|---|---|
| 전체 상영 편성·좌석 용량·판매 가능 상태 | 판매된 선택지만으로는 제공되지 않은 선택지와 미선택을 구분하기 어렵다는 점을 이해하는가 |
| 예매·취소·환불·입장 확인 시점 | 구매, 예약 상태와 실제 이용의 차이를 확인하며 시점별 가용 정보를 구분하는가 |
| 가격·할인·프로모션 | 판매량 변화에 영향을 줄 수 있는 조건을 구분하며 효과를 성급히 인과로 해석하지 않는가 |
| 영화 메타데이터·개봉 정보·공개 콘텐츠 | 신작에 대해 어떤 정보가 언제 이용 가능한지 설명하는가 |
| 노출·검색·관심 표현·비구매 행동 | 관측된 구매만으로 선호를 단정하는 한계를 설명하는가 |
| 집계 수준의 동행 조사·선택 이유 조사 | 개인 신원을 복원하지 않고도 중요한 가정을 확인하는 방법을 제안하는가 |
| 기존 예측·편성 방식과 운영 성과 | 현행 기준안, 비교 대상과 실제 도입 제약을 파악하려 하는가 |

해당 영화사가 보유한다고 확인되지 않은 데이터는 보유 사실로 간주하지 않는다. 다른 조직의 정보라면 제공 주체와 협조 조건까지 제안할 수 있다. 요청할 수 있는 모든 정보를 나열하는 답보다 우선순위가 분명한 최소 정보 계획을 높게 평가한다.

## 6. 세 제출물의 연결 확인

채점 시 문제 정의서의 주요 주장 몇 개를 골라 데모와 발표까지 따라가 본다.

| 확인 질문 | 주요 평가 항목 |
|---|---|
| 문서의 입력·설정이 데모에서 실제로 쓰이는가? | 데모의 문서 일치 |
| 목표와 제약의 의미가 화면·계산·발표에서 같은가? | 계산 가능한 정의, 문서 일치 |
| 기준안과 제안안을 공정한 조건으로 비교했는가? | 검증 계획, 확인 가능성 |
| 문서가 모의 계산이라 한 결과를 발표가 검증된 성과처럼 주장하지 않는가? | 제안의 논리와 근거 |
| 데모의 한계가 추가 데이터 요청과 현장 검증 계획으로 이어지는가? | 실행 가능한 도입 제안 |
| LLM 제안을 채택한 근거가 실제 문서·동작에서 확인되는가? | LLM 활용과 본인 검토 |

데모의 핵심 흐름, 정상·경계·실패 사례와 재실행을 직접 확인한다. 실행 불가 시 데모 실행 항목을 평가하되, 읽을 수 있는 문제 정의서와 발표까지 자동으로 0점 처리하지 않는다. 단순한 구현도 핵심 원리와 경계를 정확히 설명하면 인정한다.

LLM 활용 사례의 양이나 인위적인 오류 발견 수를 평가하지 않는다. 본인의 판단과 검토 결과를 확인한다. 문체나 AI 탐지 점수를 사고력·작성 책임의 대리 지표로 사용하지 않는다.
