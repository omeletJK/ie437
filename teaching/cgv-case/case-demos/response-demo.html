    Without Action History, adapt
    the identification strategy and validation depth

    Strategy 01

    Use natural experiments

    Use different schedules for the same film across sites/weeks as quasi-experimental variation to estimate response effects.

    Strategy 02

    Build prospective logs

    From October Shadow operation, record schedule snapshots and revisions to strengthen identification later in the PoC and Phase 2.

    Strategy 03

    Conservative identification

    Estimate effects only where assumptions are supported; state uncertainty. Observational data alone does not establish full causality.

    Strategy 04

    Redefine validation depth

    Treat H2 as partial validation and assess PoC results around H1 and H3 (Replay-based optimization gains).

    Clear limits support credible evidence— agree the scope based on data availability at kickoff.

    A6Appendix — “Data security and export”

    Process cinema data within the cinema chain’s environment
    and exclude it from global-model training

    Principle 01

    Deidentified · Aggregated data only

    The cinema chain's 47 data categories across three domains are deidentified and aggregated. No individually identifiable data is requested.

    Principle 02

    Process in the client environment

    Keep data and decision records within the cinema chain's tenant. Exclude them from provider global-model training.

    Principle 03

    Use existing paths

    Use the cinema chain's EAI · DX AI · DB paths without adding external export channels.

    Principle 04

    Deliverable ownership

    Cinema owns validation reports, Decision Logs, Replay environments, and project outputs. Support IT and security review.

    Complete security review before kickoff— configure VPC or on-premises processing where required by Cinema policy.
