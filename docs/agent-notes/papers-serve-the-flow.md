# Papers serve the flow

*The professor does not want a lecture to be a tour of a few papers; build the core conceptual flow first and cite only famous, meaningful papers that carry a step of it*

On 2026-10-11, reviewing Lecture 5 (offline MBO: NEMO / COMs / RoMA, 2021), the professor asked whether
the papers were too old or too obscure, and said they do not want a lecture that ends at "introducing
a few papers". The core flow matters; a paper belongs only if it is genuinely well known and
meaningful *and* it supports a step of that flow.

**Why:** a method-by-method tour (three parallel recipes, a benchmark table) teaches students which
papers exist, not the idea that connects them. Lesser-known variants dilute the one mechanism that
should be remembered.

**How to apply:** before keeping or adding a paper, name the step of the chapter's argument it carries;
if none, demote it to the appendix or drop it. Teach one method in depth over several surveyed. The
spine should be the field's own research lineage (for Ch 5: offline MBO from the Levine group — MINs,
COMs, Design-Bench — the same program that produced CQL for Ch 12). Do not swap that lineage for famous
papers imported from adjacent fields just for their fame (a first proposal using the optimizer's curse
and RLHF overoptimization was challenged on exactly this, 2026-10-11). This does not override placing the lab's own papers inside a research-
stream map when asked, as in [ch04-frontier-lab-papers](ch04-frontier-lab-papers.md). Source-deck topics that are demoted
still need `md/_source/source_fidelity_map.json` updated. See [demos-show-the-picture](demos-show-the-picture.md).
